# TouchDeck: uinput-эксперимент на Niri

Результат на этой машине: обычный touch (A) доставляется, но переводит фокус на панель. Эксклюзивный reader (B) обработал кнопку и движение ползунка, сохранив фокус и клавиатурный ввод в основном окне. Подробности и границы проверки — в [REPORT.md](REPORT.md).

## Зависимости и сборка

Нужны пользовательский Wayland-сеанс Niri, `electron43`, Node/npm, Python с `evdev`, `udevadm`, C-компилятор, заголовки и библиотека libinput. На проверенной CachyOS они уже были установлены. Система не обновлялась. Утилита `libinput` отсутствовала: `scripts/probe.c` использует установленную библиотеку напрямую.

```sh
npm ci
npm run build
npm run check
npm run probe:build
niri --version
niri msg --json outputs
printenv WAYLAND_DISPLAY NIRI_SOCKET
getfacl -p /dev/uinput
```

Electron и генератор запускать от обычного пользователя. При отсутствии прав остановитесь: нужны отдельно согласованные команды администратора для конкретного пользователя/устройства. Не делайте `chmod 666`, не расширяйте доступ к реальным устройствам. На проверенной машине персональный ACL для `/dev/uinput` уже существовал, событийный узел был доступен через существующие права.

## Конфигурация и окна

Выбраны DP-1 (панель, 1920×1080, scale 1) и DP-3 (основное окно, 2560×1440, scale 1). Есть также DP-2 с поворотом 90°. Если выходы отличаются, сначала измените две строки `open-on-output` и `map-to-output` в `scripts/config.py` под существующие имена.

```sh
python scripts/config.py apply
```

Скрипт создаёт датированную резервную копию `~/.config/niri/config.kdl.touchdeck-*.bak`, добавляет touch в существующий `input` и временные правила окон, запускает `niri validate`. При ошибке сразу восстанавливает исходный файл. Niri перечитывает конфигурацию сам. Файлы, генерируемые DMS, не редактируются. Уже существующий основной блок `touch` требует ручного объединения после резервной копии. Привязка в Niri относится ко всем системным touchscreen, поэтому в этом эксперименте не подключайте другие сенсоры.

Для каждого повтора выбирайте новый каталог, чтобы журналы не смешивались. В первом терминале:

```sh
mkdir -m 700 -p logs/repeat-A
python scripts/capture.py logs/repeat-A/niri.jsonl
```

Во втором:

```sh
TOUCHDECK_RUN=logs/repeat-A WAYLAND_DEBUG=1 electron43 --ozone-platform=wayland . > logs/repeat-A/wayland.log 2>&1
```

Появятся `TouchDeck-panel` на DP-1 и `TouchDeck-primary` на DP-3. Панель открывается на весь экран; Electron CSD оставляет область содержимого высотой 1051 при поверхности 1080. Правила размещения применяются при создании окон — после изменения правил приложение нужно перезапустить. Код не вызывает `focus()` и не восстанавливает фокус.

Проверьте размещение через `niri msg --json windows` и `niri msg --json workspaces`. Нативный backend подтверждается обменом `wl_surface`, `xdg_toplevel`, а для A — `wl_touch.down/up` в `wayland.log`. Один флаг запуска доказательством не является.

## A: один системный tap

В третьем терминале:

```sh
python scripts/touch.py --mode A --x 16384 --y 6000 --arm-on-primary --log logs/repeat-A/generator.jsonl
```

Генератор создаст `TouchDeck-Test`, проверит udev и libinput, напечатает путь `/dev/input/eventN`. Устройство: `INPUT_PROP_DIRECT`, `BTN_TOUCH`, ABS_X/Y, MT_SLOT (два допустимых слота, используется только нулевой), MT_TRACKING_ID, MT_POSITION_X/Y. Down получает tracking ID 1, up — -1; каждый кадр заканчивается SYN_REPORT.

Выберите основное окно вручную и печатайте тестовый текст. После трёх секунд устойчивого фокуса идёт обратный отсчёт 3–2–1, затем один контакт на 150 мс и ещё 2 секунды наблюдения. При потере начального фокуса до отправки тест отменяется. После касания генератор не восстанавливает фокус. Ожидание исходного фокуса ограничено 180 секундами.

Координаты A — нормализованные абсолютные координаты **всего выхода** в диапазоне 0–32767. Точка 16384/6000 проверена внутри большой кнопки при указанном размещении. Для другого размера/поворота сначала заново проверьте геометрию; нельзя отправлять движения до фактического попадания первого tap.

Дополнительная диагностика, пока устройство существует:

```sh
udevadm info -q property -n /dev/input/eventN
scripts/probe /dev/input/eventN
```

Ожидается `ID_INPUT_TOUCHSCREEN=1`, без `ID_INPUT_MOUSE`/`ID_INPUT_TOUCHPAD`, и `touch=1 pointer=0 keyboard=0`. Probe открывает только явно переданный узел и не захватывает его.

## B: только после неудовлетворительного A

Создайте `logs/repeat-B`, запустите capture и Electron как выше, заменив каталог. Затем:

```sh
python scripts/touch.py --mode B --socket "$PWD/logs/repeat-B/reader.sock" --x 16384 --y 6000 --arm-on-primary --log logs/repeat-B/generator.jsonl
```

Отдельный процесс reader открывает только путь устройства, созданного этим запуском, проверяет имя, vendor/product, уникальный `phys` и DIRECT, затем делает EVIOCGRAB. Генерация разрешается только после подтверждений захвата и IPC. На каждый кадр требуется подтверждение от Electron renderer; при потере reader/IPC отправка прекращается. Проверка живости выполняется перед кадрами и каждые 20 мс в паузах, тайм-аут ACK — 2 секунды. При ошибке устройство закрывается без отправки системного release после снятия захвата.

IPC — Unix-сокет `reader.sock`, режим 0600 в каталоге 0700. Принимаются только hello и ограниченные кадры контакта; длина сообщения ограничена, проверяются координаты, фаза, номер кадра, одновременно допускается один reader и один неподтверждённый кадр. Renderer имеет sandbox/contextIsolation; доступен только узкий preload API. React меняет состояние кнопки/ползунка напрямую, без DOM dispatch, `sendInputEvent`, мыши или клавиатурного синтеза.

После подтверждённой обработки первого B tap можно проверить один drag:

```sh
python scripts/touch.py --mode B --socket "$PWD/logs/repeat-B/reader.sock" --x 6553 --y 13562 --move-x 26214 --confirmed-hit --arm-on-primary --log logs/repeat-B/move.jsonl
```

Это down, 20 перемещений, up. Для B координаты масштабируются на область содержимого панели, а попадание проверяется по реальным прямоугольникам React-элементов. Эта схема проверена для одной полноэкранной панели и одного контакта; физическую калибровку она не доказывает.

Проверка потери reader (с запущенным Electron, после завершения обычных тестов):

```sh
python tests/reader_loss.py
```

Она создаёт только собственный виртуальный сенсор, дожидается ready, убивает только свой reader, проверяет ноль отправленных событий и удаление устройства. Использует `logs/B/reader.sock`; для другого каталога измените путь в тесте. Повтор требует нового `logs/B/reader-loss.jsonl`.

## Журналы и критерии

- `electron.jsonl`: focus/blur обоих окон, клавиши, системные touch-события, собственные действия B, геометрия элементов.
- `generator.jsonl` / `move.jsonl`: создание, классификация, grab/ready, отсчёт, кадры, ACK и удаление устройства.
- `niri.jsonl`: полный JSON event-stream с UTC-метками времени при получении строки.
- `wayland.log`: фактический протокольный обмен; метки Wayland имеют другую шкалу, для корреляции используйте события Electron и генератора с UTC.

Успех требует положительного события кнопки/ползунка, отсутствия `primary-blur` и переключений Niri в измерительном интервале. Совпадения фокуса только в начале/конце недостаточно. Курсор оценивается отдельным наблюдением. Журналы содержат тестовые клавиши и метаданные других окон; они сохранены локально и исключены из Git.

## Остановка и откат

Ctrl-C в генераторе прекращает отправку и закрывает UInput. Reader закрывается вместе с ним; никаких реальных мышей/клавиатур он не захватывает. Закройте оба окна Electron или нажмите Ctrl-C в его терминале; затем Ctrl-C в capture. Сокет удаляется при нормальном завершении Electron. После аварийного SIGKILL используйте новый каталог запуска; старый сокет можно удалить после проверки отсутствия процесса.

```sh
python scripts/config.py restore
niri validate
```

Restore также сначала делает резервную копию и удаляет только экспериментальные вставки, сохраняя остальные правки. Полную копию можно восстановить вручную лишь если после неё не было других изменений. Никаких служб, автозапуска или правил udev не создаётся. На завершении этой сессии окна/reader/capture остановлены, виртуальных устройств нет, исходная конфигурация восстановлена и побайтово совпала с исходной копией. ACL не изменялся.

## Проверка во время переписки в AyuGram

С теми же временными правилами и отдельным каталогом `logs/ayugram`:

```sh
python scripts/capture.py logs/ayugram/niri.jsonl --focus-only
# В другом терминале:
TOUCHDECK_RUN=logs/ayugram electron43 --ozone-platform=wayland .
# После проверки размещения панели и попадания одиночного B tap:
python scripts/touch.py --mode B --socket "$PWD/logs/ayugram/reader.sock" --x 16384 --y 6000 --confirmed-hit --taps 5 --arm-app-id com.ayugram.desktop --log logs/ayugram/generator.jsonl
```

Выберите AyuGram вручную и пользуйтесь им около 20 секунд. После трёх секунд устойчивого фокуса и отсчёта 3–2–1 будут пять контактов по кнопке с паузами по две секунды. Перед каждым контактом проверяется фокус приложения; при его уходе дальнейшие контакты отменяются. Фокус не восстанавливается. Серии ограничены пятью tap и разрешены только для B после подтверждённого попадания.

Режим `--focus-only` сохраняет только смены ID фокуса, без заголовков других окон. Снимки генератора сохраняют ID, app_id и is_focused, без заголовка AyuGram. Содержимое переписки и клавиши AyuGram не перехватываются. После теста остановите процессы и выполните `python scripts/config.py restore`.
