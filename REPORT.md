# Отчёт: виртуальная TouchDeck на CachyOS / Wayland / Niri / DMS

Дата: 1 ноября 2026, 03:05–03:12 Europe/Moscow (журналы используют UTC).

**Вывод:** системный touchscreen-ввод доставляется в Electron, но переводит фокус на панель. Вариант с эксклюзивным reader и собственной обработкой React выполнил проверенные требования: кнопка и ползунок работают, основное окно сохраняет фокус и продолжает получать клавиатуру. Это результат ограниченного эксперимента, а не проверка физической панели.

## Проверено

### Среда

- Работающий композитор PID 3312: `/proc/3312/exe --version` → `niri 26.04 (8ed0da4)`. Данные бинарника и сеанса согласуются.
- `WAYLAND_DISPLAY=wayland-1`, `NIRI_SOCKET=/run/user/1000/niri.wayland-1.3312.sock`, XDG_SESSION_TYPE=wayland. Niri IPC отвечает.
- DP-1: 1920×1080, scale 1, Normal, логическая позиция (6641,0) — выбранная панель.
- DP-3: 2560×1440, scale 1, Normal, позиция (4081,0) — основное окно.
- DP-2: 1080×1920 логических пикселей, scale 1, transform 90, позиция (3001,0). Фактически активны три выхода, хотя первоначально описаны два.
- DMS работает в quickshell PID 3638; генерируемый `dms/input.kdl` не изменялся.
- Electron 43.8.4 (`electron43`), Node 26.12.1, npm 12.2.1, python-evdev 2.0.0, libinput 1.32.0, udevadm и компилятор доступны.
- Диагностической команды `libinput` нет. Проверка выполнена через установленную libinput собственным минимальным `scripts/probe.c`, открывающим только заданный узел.
- UID Codex/Electron/генератора — 1000. `/dev/uinput` уже имел персональный rw ACL для eo; права не менялись, привилегированные команды не потребовались.

Исходные и текущие выходы: `logs/outputs.json`, `logs/outputs-current.json`; работающие процессы: `logs/runtime.json`.

### Панель и сенсор

- Electron + React + TypeScript: большая кнопка со счётчиком, range-ползунок, журнал. Отдельное основное окно логирует focus/blur и получаемые им клавиши. Глобальных перехватчиков клавиатуры нет.
- Нативный Wayland подтверждён обменом `wl_compositor`, `wl_surface`, `xdg_toplevel`; для A видны `wl_touch.down/up`, а не только флаг запуска. Журналы: `logs/A/wayland.log`, `logs/wayland-B.log`.
- Размещение проверено по Niri windows/workspaces: A panel id 112 на DP-1 (поверхность 1920×1080), primary id 111 на DP-3. Для B primary id 114. Содержимое панели B — 1920×1051 из-за CSD Electron; фактические прямоугольники элементов записаны как `geometry`.
- UInput TouchDeck-Test: DIRECT, BTN_TOUCH, абсолютные оси, Type B с MT_SLOT/TRACKING_ID/POSITION_X/Y и SYN_REPORT. В текущем генераторе доступны два слота, используется один контакт в слоте 0.
- udev: `ID_INPUT_TOUCHSCREEN=1`, нет mouse/touchpad. libinput: `name=TouchDeck-Test touch=1 pointer=0 keyboard=0`.
- Touch временно сопоставлен DP-1 через существующий блок input. Конфигурация сохранена перед изменением, принята валидатором, затем восстановлена.
- Сначала выполнен только один tap A. Его попадание и обработка подтверждены до любых движений. После неудовлетворительного A выполнен один tap B; движение B отправлено только после подтверждения его обработки.

### B: tap и движение обработаны с сохранением фокуса

Reader — отдельный процесс. Он проверяет путь созданного этим запуском устройства, уникальный phys, имя, vendor/product и DIRECT, затем захватывает только его. Подтверждение готовности поступает после EVIOCGRAB и подключения к Unix IPC. Каждый переданный кадр подтверждается renderer. React обрабатывает координаты собственной логикой; webContents.sendInputEvent, DOM dispatch, синтетические мышь/клавиатура не используются.

### Курсор — отдельное наблюдение

На вопрос о видимости и сохранении прежнего положения после tap B пользователь ответил «да остался». Это подтверждение пользователем, не инструментальное измерение координат и не видеозапись. Видимость/положение курсора для A и отдельно после движения B не установлены.

### Безопасность, проверки и откат

- `npm run check` (TypeScript strict, Python compile, Node syntax) и `npm run build` прошли. C probe собран с `-Wall -Wextra` без предупреждений.
- `tests/reader_loss.py` прошёл: после ready принудительно завершён только собственный reader, генератор завершился с ошибкой, отправленных событий 0, событийный узел удалён. Журнал `logs/B/reader-loss.jsonl`.
- Ctrl-C проверен на первом ожидающем генераторе; его устройство удалилось. Все завершившиеся тестовые устройства удалены. Итоговая проверка `/sys/class/input/event*/device/name`: TouchDeck-Test отсутствует.
- Electron, reader и capture остановлены; `reader.sock` удалён. Автозапуск, службы, правила udev не создавались. ACL не менялся.
- Перед каждой записью конфигурации создавалась отдельная копия в `~/.config/niri/config.kdl.touchdeck-*.bak`. Финальный apply/restore также проверен; `niri validate` успешен, `cmp` с первой исходной копией `config.kdl.touchdeck-20261101030532.bak` подтвердил побайтовое совпадение.

## Не прошло

- **A: сохранение фокуса.** Касание переводит фокус на Electron-панель и уводит туда клавиатуру.
- Первая временная конфигурация с повторным основным `input` была отвергнута `niri validate` и автоматически восстановлена. Исправленный вариант принят; исходная конфигурация в итоге полностью восстановлена.
- Первый запуск B reader остановился до событий: evdev.InputDevice не поддерживает context manager. Исправлено через contextlib.closing; последующие функциональные и аварийная проверки прошли.
- Две подготовительные попытки B отменены до отправки из-за ручного ухода фокуса в чат во время отсчёта. Они не засчитаны ни как успех, ни как функциональный отказ B.

## Не проверено

- Физический touchscreen, реальная калибровка, повёрнутый выход DP-2, fractional scaling и hotplug мониторов.
- Более одного контакта, длинные серии, длительная работа и производительность.
- Системный drag A после выявленного отказа фокуса.
- Внешнее инструментальное наблюдение курсора; отдельное наблюдение после движения B.
- Аварийная потеря reader посреди активного контакта: потеря подтверждена тестом до начала генерации. В коде есть проверки живости и ACK перед продолжением; это не доказательство поведения всех гонок при авариях процессов.
- Другие версии Niri/Electron и взаимодействие с реальными сенсорами. Проверенная привязка touch в Niri общая, не индивидуальная для имени устройства.

## Практическое следствие

Для этой конфигурации обычная системная сенсорная панель не удовлетворяет условию «работает без потери фокуса основного окна». Собственный reader с эксклюзивным захватом виртуального сенсора и передачей координат в React подтверждает техническую возможность нужного поведения для одного контакта. Для физического прототипа потребуется отдельно проверить доступ к конкретному устройству, калибровку и устойчивость аварийного завершения.
